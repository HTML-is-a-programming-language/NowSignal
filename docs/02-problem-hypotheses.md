## 1. 상태 표기

- `hypothesis`: 반증 가능한 형태로 검증할 주장
- `planned`: 실행 예정인 조사 또는 실험
- `not_verified`: 아직 실제 증거가 없음
- `insufficient_evidence`: 일부 증거가 있으나 결론을 내리기 부족함
- `validated`: 사전 정의한 방법과 판단 기준을 충족한 실제 증거가 있음
- `rejected`: 실제 증거가 가설과 일치하지 않음

현재 이 문서의 문제·사용자·대안·가치 주장은 별도 표시가 없는 한 모두 `hypothesis`다. 가상의 사용자 발언이나 결과는 포함하지 않는다.

## 2. 핵심 문제 가설

### H-P01 — 정보 통합 부담

- 가설: 사용자는 특정 야외·생활 활동 시간을 정할 때 날씨, 강수, 대기질, 공식 경보를 둘 이상의 화면에서 확인하고 머릿속으로 종합한다.
- 예상 맥락: 외출, 운동, 산책, 빨래, 세차, 나들이를 같은 날 할지 또는 언제 할지 결정할 때
- 현재 증거: 없음 (`not_verified`)
- 확인 질문: 최근 실제 사례에서 첫 확인부터 최종 결정까지 사용한 출처·순서·전환 이유를 회상시키고 가능하면 화면 흐름을 재현한다.
- 지지 신호: 제품 설명 없이도 여러 출처를 오가거나 수치를 직접 비교한 최근 사례가 반복 관찰됨
- 반증 신호: 대부분 한 출처 또는 일상적 감각으로 빠르고 확신 있게 결정하며 추가 통합을 원하지 않음

### H-P02 — 수치에서 행동으로의 번역 부담

- 가설: 시간대별 기상·대기질 수치를 보는 것만으로는 “언제 무엇을 할지”를 빠르게 결정하기 어렵다.
- 현재 증거: 없음 (`not_verified`)
- 확인 질문: 최근 확인한 수치 중 실제 행동을 바꾼 값, 해석이 어려웠던 값, 결정을 보류한 이유를 묻는다.
- 지지 신호: 같은 수치를 보고도 추가 검색, 개인 규칙, 타인 문의 또는 반복 확인을 사용함
- 반증 신호: 사용자가 이미 안정적인 개인 규칙을 갖고 있고 Action Brief가 결정을 더 느리게 하거나 과도하게 단순화함

### H-P03 — 활동별 최적 시간의 차이

- 가설: 같은 날이어도 산책, 달리기, 아이와 외출, 빨래 건조, 세차 등은 중요 조건과 피해야 할 시간이 달라 범용적인 “오늘 날씨”만으로 충분하지 않다.
- 현재 증거: 없음 (`not_verified`)
- 확인 질문: 활동별로 중요하게 보는 조건, 포기 조건, 시간 이동 가능 범위를 실제 사례로 묻는다.
- 지지 신호: 활동마다 다른 threshold 또는 Hard Block을 설명하고 시간대를 이동한 사례가 있음
- 반증 신호: 활동별 차이가 작거나 개인차가 너무 커서 공개 데이터만으로 유용한 기본값을 만들 수 없음

### H-P04 — 상충 신호 처리

- 가설: 강수는 없지만 대기질이 나쁘거나, 기온은 적절하지만 오존·강풍·공식 경보가 있는 등 신호가 상충할 때 사용자는 판단 확신을 잃는다.
- 현재 증거: 없음 (`not_verified`)
- 확인 질문: 서로 다른 앱·지표가 다른 결론을 준 최근 상황과 최종적으로 무엇을 더 신뢰했는지 묻는다.
- 지지 신호: 상충 상황에서 반복 확인, 계획 취소·지연, 출처 우선순위 혼란이 관찰됨
- 반증 신호: 공식 등급이나 개인 규칙 하나로 일관되게 해결하고 추가 설명을 불필요하게 여김

### H-P05 — 큰 변화의 재확인 부담

- 가설: 사용자는 계획 후에도 강수 시작 시각, 대기질, 공식 특보가 크게 바뀌었는지 다시 확인해야 하지만 모든 변화를 알림으로 받고 싶지는 않다.
- 현재 증거: 없음 (`not_verified`)
- 확인 질문: 계획 후 재확인 시점, 놓쳐서 불편했던 변화, 불필요했던 알림의 종류와 대응을 묻는다.
- 지지 신호: 행동에 영향을 준 변화를 놓친 경험과 알림 피로가 함께 반복됨
- 반증 신호: 현재 알림으로 충분하거나 변경 알림 자체를 원하지 않음

### H-P06 — 대안 탐색 비용

- 가설: 원래 활동 시간이 나빠졌을 때 가까운 다른 시간이나 실내·대체 장소를 다시 찾는 과정이 번거롭다.
- 현재 증거: 없음 (`not_verified`)
- 확인 질문: 계획을 바꾼 최근 사례에서 대안을 찾은 과정, 거리·운영시간·비용·실내외 조건을 묻는다.
- 지지 신호: 계획 악화 후 검색을 처음부터 반복하거나 대안을 찾지 못해 활동을 포기함
- 반증 신호: 이미 고정된 대안이 있거나 지역 공개정보의 Coverage·Freshness가 기대를 충족할 수 없음

### H-P07 — 근거와 신선도가 신뢰 판단에 필요

- 가설: 행동 추천에서 출처, 관측·발표 시각, 유효시간, 불확실성을 바로 확인할 수 있으면 사용자가 추천을 맹목적으로 따르지 않고 적용 여부를 판단하는 데 도움이 된다.
- 현재 증거: 없음 (`not_verified`)
- 확인 질문: 어떤 상황에서 원본을 확인하는지, “최신”이라고 판단하는 기준, 출처 없는 추천에 어떻게 반응하는지 묻는다.
- 지지 신호: 중요한 결정일수록 원본·시각·기관을 확인하고 오래되거나 상충하는 정보에서 행동을 보류함
- 반증 신호: Evidence가 의사결정에 쓰이지 않거나 정보 과부하만 증가시킴

### H-P08 — 위치 권한 없이도 핵심 가치 유지

- 가설: 정확한 위치 제공을 원하지 않는 사용자는 관심지역 수동 선택이 있으면 핵심 Brief를 사용할 수 있다.
- 현재 증거: 없음 (`not_verified`)
- 확인 질문: 위치 권한 허용 기준, 원하는 위치 정밀도, 수동 지역 선택의 허용 가능한 비용을 묻는다.
- 지지 신호: 위치 권한은 거부하지만 시·군·구 또는 관심지역을 직접 선택해 과제를 완료함
- 반증 신호: 수동 선택이 지나치게 번거롭거나 반대로 정확한 GPS 없이는 핵심 추천 품질이 성립하지 않음

연령, 직업, 가족형태로 문제를 단정하지 않는다. 실제 행동 빈도와 최근 결정 사례를 기준으로 모집한다.

## 4. 현재 대안 가설

특정 서비스의 기능·시장점유율을 주장하지 않는다. 실제 사용 앱과 만족도는 인터뷰에서 수집하기 전까지 `not_verified`다.

| 대안 범주 | 사용자가 얻을 수 있다고 가정한 가치 | 잠재 Gap 가설 | 전환 비용 가설 | 검증 방법 |
| --- | --- | --- | --- | --- |
| 날씨 앱·포털 | 현재·시간대별 기상 확인 | 활동별 행동으로 직접 번역하려면 사용자가 추가 판단할 수 있음 | 익숙한 UI, Widget, 이미 설정한 지역 | 최근 사례의 화면 흐름 관찰 |
| 대기질 앱·포털 | 미세먼지·초미세먼지·오존 확인 | 날씨·활동 시간과 별도로 비교할 수 있음 | 익숙한 등급과 알림 | 어떤 지표를 언제 확인하는지 질문 |
| 공식 재난·안전 채널 | 공식 경보와 행동지침 확인 | 일상 활동 계획과 별개로 도착하거나 해석될 수 있음 | 높은 기관 신뢰, 기본 알림 | 경보를 받은 실제 사례와 행동 변화 확인 |
| 지도·지역정보·행사 검색 | 장소, 거리, 운영정보 탐색 | 당일 날씨·대기질과 대안을 직접 결합해야 할 수 있음 | 저장 장소, Review, 검색 습관 | 악천후 때 대안 탐색 Journey 재현 |
| 일반 검색·대화형 AI | 질문형 요약과 아이디어 | 출처·Freshness·공식 경보 보존이 불명확할 수 있음 | 질문 자유도와 낮은 학습 비용 | 동일 과제 비교와 Evidence 확인 행동 관찰 |
| 개인 규칙·경험·주변 사람 | 빠르고 익숙한 판단 | 급격한 변화·상충 데이터에 취약할 수 있음 | 별도 앱이 필요 없음, 신뢰가 축적됨 | 개인 threshold와 실패 사례 질문 |
| 활동 포기·나중에 재확인 | 잘못된 결정을 피함 | 기회 손실 또는 반복 확인 비용이 생길 수 있음 | 가장 안전하고 간단함 | 포기·지연의 실제 영향 질문 |

NowSignal AI의 실질적인 경쟁자는 단일 앱이 아니라 사용자가 이미 조합한 workflow일 가능성이 있다 (`hypothesis`). 따라서 “기능이 더 많다”가 아니라 기존 workflow보다 더 빠르고 검증 가능하게 결정할 수 있는지를 비교한다.

## 6. 문제 검증 지표

아래 지표는 인터뷰·관찰을 일관되게 coding하기 위한 정의다. 값은 모두 `not_verified`다.

| 지표 | 계산 정의 | 증거 규칙 |
| --- | --- | --- |
| `recent_problem_recurrence_rate` | Concept를 설명하기 전에 최근 14일 내 관련 결정을 구체적으로 회상한 적격 참여자 / 전체 적격 참여자 | 날짜·활동·결정·결과가 있는 사례만 분자에 포함 |
| `multi_source_reconciliation_rate` | 한 결정에서 둘 이상의 정보 출처 또는 사람·개인 규칙을 조합한 적격 참여자 / 전체 적격 참여자 | 단순히 앱을 보유한다는 답은 제외 |
| `decision_consequence_rate` | 정보 확인 결과 시간·준비물·장소·취소 중 하나를 바꾼 적격 참여자 / 전체 적격 참여자 | 실제 최근 사례만 포함 |
| `unresolved_conflict_rate` | 상충 정보 때문에 재확인·보류·후회가 발생한 사례 / 수집한 상충 정보 사례 | 조사자가 만든 가상 scenario 반응은 별도 집계 |
| `current_workflow_satisfaction` | 현재 workflow 만족 이유와 불만 이유의 구조화된 응답 | 평균 점수만 쓰지 않고 근거 문장과 행동을 함께 coding |
| `switching_intent_with_cost` | 위치 권한·새 UI·알림 설정 등 실제 비용을 설명한 뒤에도 비교 사용 의향을 보인 적격 참여자 / 전체 적격 참여자 | 단순한 “좋아 보인다”는 제외 |

### 초기 판단 기준

다음은 작은 탐색 표본을 위한 `planned_threshold`이며 시장 통계나 달성 결과가 아니다.

- 우선 문제를 유지할 후보 조건: 적격 참여자의 절반 이상이 Concept 제시 전에 최근 문제 사례를 말하고, 그중 일부가 반복 확인 또는 결정 변경의 구체적 비용을 설명한다.
- 축소 후보 조건: 문제는 반복되지만 특정 활동 또는 특정 상황에서만 강하면 해당 범위로 좁힌다.
- 전환 후보 조건: 최근 사례가 드물거나 현재 workflow 만족도가 높고 비교 Prototype에서도 결정 개선이 관찰되지 않는다.
- 판단 보류 조건: 모집이 한 행동 맥락에 치우치거나 회상 품질이 낮으면 `insufficient_evidence`로 남기고 표본을 보완한다.

“절반 이상”은 탐색 우선순위를 정하기 위한 운영 기준일 뿐 통계적 유의성이나 시장 수요를 뜻하지 않는다.

## 7. 검증 순서

1. `planned`: Screening과 2건의 Pilot Interview로 질문의 유도성·이해도를 점검한다. Pilot 결과는 본 표본과 구분한다.
2. `planned`: 최근 실제 행동 중심의 Problem Interview를 실행해 H-P01~H-P08을 coding한다.
3. `planned`: 가장 반복된 두세 개 활동만 골라 Raw Data UI와 Action Brief UI를 비교한다.
4. `planned`: Data feasibility와 안전 Guardrail을 통과한 뒤 Prototype Usability Test를 실행한다.
5. `planned`: 역사 데이터 Backtest로 Freshness·Conflict·Official alert·Activity window를 검사한다.
6. `planned`: 명시적 동의를 받은 소규모 참여자와 3주 Beta를 실행한다.
7. `planned`: 잘못된 추천, 불필요한 알림, 제품 변경, 재검증 결과를 실제 값으로 기록한다. 직접 인용은 Pilot에서 수집하지 않으며, 별도 인용 동의를 받은 후속 연구에서만 후보로 다룬다.

## 8. 업데이트 규칙

각 인터뷰·실험 후 가설 ID별로 다음을 추가한다.

- 실행일과 연구자
- 실제 참여자 수와 적격·제외 기준
- 원자료 위치와 Consent 상태
- 지지·반증 사례 수
- Pilot은 비식별 사례 요약만 기록한다. 대표 직접 인용문과 익명 참여자 ID는 별도 인용 동의를 받고 원문 대조가 가능한 후속 연구에서만 기록한다.
- 해석 한계와 대안 설명
- 상태 변경과 제품 결정

직접 인용문은 Pilot에서는 추가하지 않는다. 후속 연구에서 별도 인용 동의를 받고 실제 녹취·Note와 대조할 수 있을 때만 추가한다. 실행하지 않은 인터뷰, 만족도, 전환 의향, 성과 수치는 작성하지 않는다.
